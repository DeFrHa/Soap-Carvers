# Soap Carvers – notes for Claude / contributors

A "friendslop" first-person 3D game: physics-y, wonky, colorful low-poly fun.
Players carve a giant bar of soap into a target shape (v1: a swan) against
the clock. It is single-player for now but built so a network layer
(Netcode for GameObjects or FishNet) can be added later.

## Project owner notes

- Unity version: 6000.3.6f1, 3D, URP, new Input System.
- Put all scripts in `Assets/Scripts`.
- Commit directly to `main`.

## Tech

- **Unity 6000.3.6f1**, **URP**, **new Input System** (actions are built in
  code; there is no `.inputactions` asset), C#.
- UI uses **UGUI with legacy `UnityEngine.UI.Text`** and the built-in
  `LegacyRuntime.ttf` font, so the TextMeshPro essentials import isn't needed.
- No external assets or packages beyond URP, Input System and UGUI.
- Everything visual comes from Unity primitives and code-generated meshes and
  materials (`MaterialFactory`).

## Hard rules

1. **Soap is modified only through `SoapBlock.ApplyCarve(SoapCarveCommand)`.**
   `CarveSphere`/`CarveCapsule` are thin wrappers around it. Never write to
   `SoapBlock.Grid.Density` from anywhere else. Every applied command is
   appended to `SoapBlock.CarveLog`. The soap state is fully determined by
   that ordered log (`ReplayLog` rebuilds it). Commands store block-local
   positions.
2. **Item state changes go through `ItemManager.Execute(ItemCommand)`**
   (pick up, drop, throw, place). Placeable items override
   `Holdable.CanBePlaced`/`TryGetPlacement`/`PlaceAt` (the ladder leans, dynamite
   sticks to soap). Round flow goes through
   `GameManager.Request*` methods. This is the seam where networking will sit:
   clients send commands, the host executes them.
3. **Input is separate from actions.** `PlayerInputHandler` only reads devices.
   `PlayerActions`, `PlayerMotor` and `PlayerLook` consume its values. A remote
   player simply won't have an input handler.
4. **No static singletons for player-specific state.** Look things up with
   serialized references (wired by `SceneBuilder`) or `FindFirstObjectByType`
   for world managers. Player id lives on `PlayerActions.PlayerId`.
5. Tools do nothing when the round is over (`Tool.ToolsEnabled`, and
   `SoapBlock.CarveFilter` set by `GameManager` rejects late carves).
6. Debris, camera shake and explosion flashes are cosmetic and
   non-deterministic. Keep them out of game state.
7. The ladder and scaffolds are real rigidbodies: their pose is physics state
   (a future network transform), not command state. Climbing works through
   `ClimbZone` triggers; pushing heavy things through `IPushable`.

## Scene generation

- The scene is generated, not hand-built. To change the layout, edit
  `SceneBuilder` and re-run **Soap Carvers → Create Playable Scene**, which
  overwrites `Assets/Scenes/SoapCarvers.unity` and the materials. It keeps
  `GameSettings.asset` if one exists.
- `GameBootstrap` on an empty GameObject builds the same scene at runtime.
- `SceneBuilder` builds under an inactive root and detaches objects in
  dependency order, so components can rely on their serialized refs in
  `Awake`. Cross-object initialisation that needs another object's `Awake`
  belongs in `Start`.
- Layer: `Hologram` (preferred index 31; `Layers.Hologram` falls back to 31 if
  it is unnamed). The main camera excludes it; the blueprint camera renders
  only it.

## Conventions

- Unity 6 APIs: `FindFirstObjectByType`/`FindObjectsByType`,
  `Rigidbody.linearVelocity`/`linearDamping`, `PhysicsMaterial`. Avoid
  deprecated APIs.
- Soap rendering: smooth marching cubes normals from the density gradient,
  0.125 m voxels, densities clamped to ±2 voxels (`VoxelGrid.MaxDensity`). Chunk
  rebuilds are budgeted per frame (`GameSettings.maxChunkRebuildsPerFrame`).
- One MonoBehaviour/ScriptableObject per file, file name = class name.
- Comment the non-obvious math (marching cubes, SDFs, scoring), not the obvious.
- Tunables go in `GameSettings` (round length, block/voxel size, tool radii, ...).
- Coordinates: soap block pivot is the center of its bottom face at the world
  origin. Players spawn at z = -14 facing +Z (the block's "front").
  `TargetShape` SDFs use normalized block space `[-1,1]^3`, +Y up, -Z = front.

## Extending

- **New tool:** subclass `Tool` and implement `Use()` (override
  `OnStartUse`/`OnStopUse` for continuous tools). Carve only via
  `Soap.CarveSphere/CarveCapsule`. Add a `Build<Tool>` method in `SceneBuilder`.
  See `WireCutterTool.cs` for the planned 2-player tool.
- **New target:** subclass `TargetShape`, compose `Sdf.*` primitives, and
  register it in `TargetLibrary`. Select it with `GameSettings.targetShapeName`.

## Checking code without Unity

`Tools~/compile-check/run.sh` compiles `Assets/Scripts` against Unity 2021.3
reference DLLs from NuGet, with an Input System stub. Unity 6 names are shimmed,
so it catches syntax, type and naming errors but not Unity 6 API drift. It
needs the dotnet SDK. Always also check in the real editor.
